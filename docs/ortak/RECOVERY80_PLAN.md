# Persistent private recovery80

This is the next implementation/acceptance boundary after native Work80 and
persistent lifecycle checkpoint `c5d50e7`. Historical77/78 recovery selections
remain immutable and do not describe the reboot-created company or its storage.

Implemented and exercised: the installed `backup` / `verify-backup` commands
captured five cold volumes, selected private/app state, immutable native packages
and image exports. Main156 and Honcho26 tables matched complete logical row,
catalog and sequence hashes after actual offline PostgreSQL startup. All five
restored trees and the inert host archives matched; image reload and separate
Hermes journal integrity/foreign-key checks passed. The source reopened with its
existing resources. See [operations and exact receipts](PERSISTENT_PRIVATE_OPERATIONS.md).
This is offline restore verification with retained targets, not automatic active
installation replacement or a new controller generation activation.

The source is the registered `~/.local/share/ortak/private-v0` installation:
schema80, current six container IDs, four immutable native services, the private
native bundle, all three employees and the one explicitly shared OAuth store.
No preserved Cem/Zeynep or pre-reboot resources enter the new inventory.

Capture must hold the lifecycle operation lock, verify the selected owners and
close ingress/native application writes. Existing pending work must drain before
the controller and stores stop. Read the five exact cold volumes: PostgreSQL,
Redis, MinIO, Honcho PostgreSQL and the Hermes journal. Readers are pinned,
bounded, read-only, offline helpers with no Docker socket or provider entrypoint.
Freeze selected private configuration/signers/OAuth/profiles, app data, native
artifacts and image selections with mode0700/0600 storage and no secret output.
Exclude build caches, source checkouts, old backups and unrelated home files.
Every phase has an intent and completion receipt; failure retains its partial
output and the caller can resume the original registered services.

Restore must create new labeled empty destinations and refuse existing ones.
It never writes an archive into a source volume or silently replaces the active
installation. Validate archive names, types, sizes, hashes and all Linux metadata
before comparing restored trees; preserve the two reviewed MinIO xattrs. Start
only the two restored database servers with their exact pinned images, no host
ports and no external network. Compare schema80 migration checksums, public
catalog/table metadata, Work/artifact hashes, frozen conversation/Work snapshots,
review decisions, outbox and memory identities. Inspect the restored journal
without dispatching its historical start keys. Restore verification does not
grant permission to activate a second controller/worker with cloned ownership.

The full source remains selected while verification targets are retained.
After capture, reopen the source through `bin/ortak start` and verify unchanged
identity/data and the native read path. Only a successful recorded restore can
be described as a usable backup. The earlier pre-upgrade79 dump and cold archive
are still merely parsed/hashed files. A complete Mac reboot and recovery on a
different machine remain separate claims; no rehearsal result implies either.
